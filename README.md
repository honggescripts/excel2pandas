# excel2pandas

> **把 Excel 里的业务公式，变成能批量跑、能逐格对账、能进 Git 的 Pandas 代码。**

一句话说清它解决的问题：**业务规则活在 Excel 的公式里——而 Excel 跑不了批量、进不了版本库、没人敢改。**

它不做"Excel 转 CSV"，不做执行引擎，不做双向同步。它只做一件窄事：

```
读一遍模板样板行的公式  →  生成一份自包含的 Python 文件  →  批量跑 N 条记录  →  逐格对账，用数据证明没算错
```

---

## 一、行业痛点

Excel 是业务的心脏，也是工程的沼泽。凡是"用 Excel 算钱"的团队，几乎都在同一个坑里：

| 痛点 | 现场表现 | 后果 |
|---|---|---|
| **业务规则锁死在公式里** | 定价/报价/测算规则全在单元格公式里，没有文档，改动靠口口相传 | 规则无法评审、无法版本化；改错一次，错一批单 |
| **人工翻译必错，而且错得无声** | 几十上百个公式手抄成 Python | `ROUND` 在 Excel 是"四舍五入远离零"、在 numpy 是银行家舍入；`SUMIFS` 无匹配返回 `0`、`XLOOKUP` 无匹配返回 `#N/A`——**pandas 一个错都不报，直接把一批错数交给你** |
| **翻译完无法自证正确** | 只能抽几个数字眼看一下 | "看起来对" = 没有对账基线，上线靠运气 |
| **批量是死结** | 一条一条填 Excel，或按模板复制 N 份 | 几十条要几十分钟；上百条不敢想。而手工定价列**每行值都不同**，复制没用 |
| **改一次规则代价极高** | 同一个魔法值（如税率）在几十个公式里重复出现 | 改一处要全文搜索，漏一处就是隐性 bug |
| **换数据源等于重做** | 路径硬编码在公式和脚本里 | 台账换一个版本，整条链路重来 |
| **懂业务的不懂 pandas，懂 pandas 的不懂公式** | 两边无法对话，靠中间人转译 | 转译层本身就是错误率最高的环节 |

**根因只有一个**：Excel 是「可视化计算器」，不是「可执行规格」。它算得对，但**不可批处理、不可测试、不可追溯**。

而这恰恰是工程化的三件事。所以问题从来不是"Excel 好不好用"，而是——**怎么在不动业务规则的前提下，把公式变成工程资产。**

---

## 二、这个项目解决了什么

四条，每条都有实测证据，不是设想。

### 1. 公式 → 代码：自动翻译，覆盖率可量化

不是"支持常见函数"，而是**按 42 个内置函数 + AST 递归下降**逐列翻译，并明确告诉你**转成功了几个、失败了几个**。

> 实测（真实模板，已脱敏）：**105 列 / 79 个公式列 → 转换成功 79，失败 0，覆盖率 100%。**

### 2. 对账：用逐格 diff 证明没算错

这是整个项目**最不可替代**的一环。生成完代码后，它会把生成结果与 **Excel 的缓存值**逐格比对，输出五类判定：

| 判定 | 含义 |
|---|---|
| ✅ **OK** | 完全一致 |
| ⚠️ **精度** | 数值差异在宽/严容差之间（浮点噪声） |
| ⚪ **空值** | 一方是 NaN |
| ❌ **逻辑** | 值真的算错了 |
| 🟡 **Excel侧错误** | 单元格本身是 `#REF!` / `#NUM!`（模板自己的问题，**不计入一致率分母**） |

**一致率 = OK /（比较格数 − Excel侧错误）**，是一个可复现、可写进验收文档的数字。

> 实测：**一致率 100.00%**。演示案例：**11/11，一致率 100.00%**。

### 3. 批量：一次 N 条，不是一次一条

生成代码是向量化的，`run_batch` 按 chunk（默认 200 条）批量调用，工作簿句柄与 sheet 缓存跨 chunk 复用，支持**断点续传**和**分块失败自动降级单条重试**。

> 实测：**50 条记录 / 100+ 列 / 13 张外部表 / 依赖表最大 8.8 万行 → 约 30 秒。**

### 4. 可维护：规则集中、每列可回溯

| 你关心的 | 项目给的 |
|---|---|
| 业务规则改了怎么办 | 魔法值全抽到 `CONFIG` 字典，**改规则只改一段**；`business_rules.md` 记录每个常量被哪些列使用 |
| 换数据源怎么办 | 只改 `FILE_PATHS` 一行 |
| 这行代码对应哪个公式 | **每列上方保留原公式**（`# H2: =ROUND(E2*1.13,2)`），对账时可直接追溯 |
| 哪些列不可信 | 转换失败的列**不填 NaN**，而是保留 Excel 兜底值 + `_fail` 后缀，结果表整体仍可用，且一眼看出风险位置 |
| 报错定位 | 运行时异常会被**映射回 Excel 单元格地址**（列字母 + 列名 + 原公式 + 行号） |

## 三、这个项目不解决什么

边界比能力更重要。以下是**明确不做**的：

| 不做 | 说明 |
|---|---|
| ❌ **不保证业务逻辑正确** | 它保证的是**与 Excel 一致**。如果 Excel 本身算错了，代码会忠实复制这个错误。**对账证明的是"没抄错"，不是"没算错"。** 业务正确性仍需人来审 |
| ❌ 不是通用 Excel 转换器 | 只针对「有一行样板行、每行结构同构」的测算/报价/定价类模板。流水账、数据录入表不适用 |
| ❌ 不做双向同步 | 单向：Excel → 代码。生成后改代码就是改代码，**不要回头改 Excel 再生成** |
| ❌ 不支持跨工作簿引用 | `[Book1.xlsx]Sheet1!A1` → 失败列 |
| ❌ 不支持数组公式 / 动态数组 / 命名区域 / 循环引用 | 循环引用会在拓扑排序阶段直接报错 |
| ❌ 不支持 `TEXT` 格式化 | 格式规则无法自动翻译成数值语义（代码里主动抛错，落到失败列） |
| ❌ 不支持 `HLOOKUP` / `LOOKUP` / 单独的 `MATCH` | `LOOKUP_FUNCS` 里预留了名字但未实现，会明确报「暂不支持」而非静默降级。`INDEX` 只支持 `INDEX(列, MATCH(...))` 两参数形式 |
| ❌ 不处理图表 / 透视表 / 宏 / VBA / UDF / 条件格式 | 只处理单元格公式 |
| ❌ 不保证常量命名有业务含义 | 未命中命名映射的魔法值走启发式命名（`_rate_0_05`），需人工在 `config_names.json` 补名 |

还有一个**使用前提**：对账基线取自 Excel 的**缓存值**。如果模板在 Excel 里没重算过（缓存过期），基线本身就不可信——**生成前请先在 Excel 里打开并保存一次**。

## 四、技术路径

```
① 读簿建模型      双读：公式视图 + 缓存值视图 → 列建模（数据/公式/空）→ 分层 + 冲突检测
        ↓
② 公式 → AST      tokenizer + 递归下降解析 → 函数注册表派发 → 生成 pandas 表达式
        ↓
③ 依赖排序        建依赖图 → 全局拓扑排序（分层只作统计，冲突自动降级）
        ↓
④ 渲染产物        自包含 .py（内嵌 runtime）+ CONFIG 抽取 + 3 份报告 + 指纹缓存
        ↓
⑤ 执行            单条 / 分块批量 / 断点续传 / 异常映射回 Excel 单元格
        ↓
⑥ 逐格对账        与 Excel 缓存值 diff → 五类判定 → 一致率
```

### 四个关键取舍

| 决策 | 为什么不能走捷径 |
|---|---|
| **公式解析用 tokenizer + 递归下降 AST**，不用字符串正则 | 真实模板里的语法噪声：`_xlfn.` 前缀 26 处、整列引用 `B:B` 26 处、`VLOOKUP(E:E, …)` 用整列当查找值 3 处。**用正则硬吃必炸**——字符串里的函数名、嵌套参数、括号配对，每一项都是一个补丁。多花约 250 行，换来这些情况天然正确 |
| **执行顺序用全局拓扑排序**，分层只作统计 | 真实模板存在**跨层反向依赖**（低层列引用高层列）。按分层顺序输出，赋值语句会排在被依赖列之前——而该列已被读成全 `NaN`，**pandas 不报错，静默算错**。所以检测到冲突必须降级为全局拓扑 |
| **`calc(primary_values, file_paths, inputs)` 三参数** | `inputs` 是很容易漏的一个。手填列（手工定价、上牌费这类）**每行值都不同**，样板行的值只能当兜底默认值。没有 `inputs`，批量跑整批都会用同一个值算 |
| **对账器独立成模块**，不折进执行器 | 对账的独立性就是它的价值。如果它和执行共用一套解析逻辑，就变成了"自己证明自己对" |

## 五、项目亮点

| 亮点 | 说明 |
|---|---|
| **5 模块内聚架构** | `reader` / `converter` / `generator` / `runner` / `verifier` + `_runtime` + CLI，包本体 3506 行。模块边界按「职责 + 是否共享同一次遍历」划分，不按概念分文件 |
| **产物自包含** | 生成的 `.py` 内嵌运行时库，**不依赖本包、不需要安装 excel2pandas**，可以直接拷给同事跑 |
| **指纹缓存** | 生成键 = 文件路径 + 大小 + mtime + sheet + 样板行 + 版本号。Excel 没变就跳过生成（`--force` 强制） |
| **断点续传** | `--progress` + `--resume`，批量跑到一半中断可续 |
| **失败降级不中断** | 分块批量失败 → 自动降级单条重试并记录是哪条挂了，不让一条坏数据带走整批 |
| **异常映射回 Excel** | Python 异常 → Excel 列字母 / 列名 / 原公式 / 行号。不用对着 traceback 猜是哪一列 |
| **模板探针** | `probe/probe_template.py` 先扫一遍模板结构（sheet、维度、公式规模、外部表、语法噪声），接手新模板时**先跑它建立预期** |
| **函数注册表可扩展** | 新增函数一个装饰器，或在 `_runtime.py` 补实现 |
| **示例可一键复现** | `examples/build_examples.py` 从造模板到对账全流程一条命令重建，**不是手放的样例文件** |

## 六、生成的 pandas 代码亮点

这是最终交付物，重点看它。

### 1. 向量化：一次映射全表，**0 处 merge**

跨表查找与条件聚合全部由 `_lookup` / `_aggif` 一次性映射到整列，返回**位置对齐数组**：

```python
# G2: =VLOOKUP(C2,运费价目!$A:$B,2,0)
df['__tmp_lk_01'] = _lookup(_sheet('运费价目'), 'A', 'B', df['类目'], not_found=None)
df['头程运费'] = df['__tmp_lk_01']
```

**生成代码里没有任何 `merge`。** 这一点很关键——多次 merge 会打乱行序、放大键重复问题、需要额外的 `_row_id` 兜底重排。这里全部规避了：

- 右表按主键 `drop_duplicates(keep="first")` 后建索引 → 与 Excel「首次命中」语义一致
- 输出是 `map` 出来的**位置对齐数组**，天然与主键行序一一对应
- 无匹配语义按函数分别处理：`XLOOKUP` → `NaN`，`SUMIFS/COUNTIFS/MAXIFS/MINIFS` → `0`，`AVERAGEIFS` → `NaN`

### 2. 对账工整：每列一行原公式，报告可当验收件

```python
# H2: =ROUND(E2*1.13,2)
df['含税成本'] = _round(((df['成本价']) * (CONFIG['含税系数'])), 2)

# N2: =ROUND(L2-M2-K2-J2,2)
df['毛利'] = _round(((((((df['参考售价']) - (df['平台佣金']))) - (df['单件成本']))) - (df['推广费'])), 2)
```

- **列顺序与 Excel 完全一致**，返回时按原表头顺序裁剪
- **每列上方保留原公式**，diff 时可以直接对照
- 临时列统一 `__tmp_` 前缀，**返回前清理干净**，不污染业务表
- 列级容差：`verifier` 支持按列覆盖 `rtol` / `atol`，金额列和比率列可以给不同精度
- 对账报告分五类 + 逐格差异明细，**可以直接当作迁移验收件附在交付文档里**

### 3. 易于回溯：改规则改一段，换源改一行

```python
# 业务规则集中在这里 —— 改规则只改这一段
CONFIG = {
    "含税系数": 1.13,
    "_rate_0_05": 0.05,
    "年化费率": 0.06,
    ...
}

# 源文件路径：换数据源只改这里
FILE_PATHS = {
    "main": r"examples\demo_template.xlsx",
}
```

配合 `business_rules.md`——它列出**每个常量的值、原始字面量、被哪些列使用**，常量与列的对应关系不用翻代码。

### 4. 可独立运行：给个主键就能跑

```bash
python generated_code.py SKU-10001
```

文件底部自带 `__main__` 入口，转置打印结果。发给业务同事时**不需要任何环境说明**。

### 5. 三分类输出：失败不静默

| 类型 | 生成代码 | 输出列名 |
|---|---|---|
| 数据列 | 不生成赋值（作为输入参数） | 原列名 |
| 成功列 | 生成赋值语句 | 原列名 |
| **失败列** | **不生成赋值，保留 Excel 兜底值** | 原列名 + **`_fail`** |

失败列不填 `NaN`——这样批量结果整体仍然可用，且**一眼看出哪几列不可信**，而不是整张表被污染。

## 七、快速开始

### 安装

```bash
pip install -r requirements.txt
# 国内建议走镜像
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

依赖：`pandas` / `openpyxl` / `numpy-financial`（财务函数用）。
也可 `pip install -e .` 后直接用 `excel2pandas` 命令。

### 跑通演示案例

仓库自带一份**虚构的电商定价测算模板** `examples/demo_template.xlsx`：

```bash
# ① 生成：读 Excel 样板行 → 出代码 + 3 份报告
python -m excel2pandas generate \
    --file examples/demo_template.xlsx \
    --sheet "定价测算" --row 2 \
    --out examples/

# ② 单条调试
python -m excel2pandas run --code examples/generated_code.py --key "SKU-10001"

# ③ 批量：CSV 清单 + 断点续传
python -m excel2pandas run --code examples/generated_code.py \
    --keys examples/keys.csv --progress examples/progress.json --resume \
    --out examples/result.xlsx

# ④ 一键对账：生成代码 vs 模板缓存值，逐格 diff
python -m excel2pandas verify --code examples/generated_code.py \
    --excel examples/demo_template.xlsx \
    --sheet "定价测算" --row 2 --key "SKU-10001" \
    --report examples/verify_report.md
```

**想从零重建上面全部产物**（含演示模板本身）：

```bash
python examples/build_examples.py
```

### 接手自己的模板

```bash
# 先探针：看结构、看公式规模、看语法噪声
python probe/probe_template.py --file "你的模板.xlsx" --sheet "目标sheet" --row 2
```

## 九、支持边界与已知的坑

### 函数支持

**42 个注册函数**，另有跨表查找与条件聚合走**专用节点处理**（因为它们要生成临时列，不占注册表）：

| 类别 | 覆盖 | 机制 |
|---|---|---|
| 算术/比较 | `+ - * / ^ %`、`= <> < > <= >=`、字符串拼接 `&` | 运算符 |
| 逻辑 | `IF / IFS / AND / OR / NOT / IFERROR / IFNA` | 注册 |
| 数学 | `ABS / ROUND / ROUNDUP / ROUNDDOWN / INT / CEILING / FLOOR / MAX / MIN / SUM / PRODUCT / SQRT / MOD / POWER` | 注册 |
| 文本 | `TEXTBEFORE / TEXTAFTER / CONCAT / TRIM / LEFT / RIGHT / LEN / VALUE` | 注册 |
| 引用 | `ROW / COLUMN`、同表引用、`$` 绝对/混合引用、表头行引用（`$A$1`） | 注册 + 渲染 |
| 查找 | `XLOOKUP`（含 `if_not_found`）/ `VLOOKUP`（精确）/ `INDEX(列, MATCH(...))` | **专用节点** → 临时列 |
| 条件聚合 | `SUMIFS / COUNTIFS / AVERAGEIFS / MAXIFS / MINIFS` | **专用节点** → 临时列 |
| 财务 | `RATE / FV / PV / PMT / NPER / IPMT / CUMIPMT` | 注册（`numpy_financial`） |

> ⚠️ 口径说明：`TEXT`、`HLOOKUP`、`LOOKUP`、单独的 `MATCH` **在代码里能识别但主动拒绝**——分别抛「不支持 TEXT 格式化」「暂不支持」。
> 主动拒绝而不是静默降级，是为了让这类列**明确落到失败列**，而不是生成一份看起来正常、实际算错的代码。

**新增函数**：注册表接口

```python
from excel2pandas.converter import register_function

@register_function("MY_FUNC")
def _f_my_func(args, node, ctx):
    return f"_my_func({', '.join(args)})"
```

再在 `_runtime.py` 补运行时实现；生成代码会自动内嵌被用到的 helper。

### Excel 语义陷阱清单

这些是**踩出来的**，不是查文档抄的。每一条都对应真实模板里出现过的噪声。

| # | 坑 | 后果与处理 |
|---|---|---|
| 1 | **`_xlfn.` 前缀** | openpyxl 读新版函数带前缀（`_xlfn.XLOOKUP`）。不剥掉，**所有 XLOOKUP 一个都转不了**（实测 26 处） |
| 2 | **越界 `VLOOKUP`** | `VLOOKUP(A2,'台账'!B:H,8,0)` —— `B:H` 只有 7 列却取第 8 列，Excel 返回 `#REF!`。生成器按「从起始列偏移 7 列」自动纠正，并在报告里提示人工确认 |
| 3 | **文本数字隐式转换** | 单元格存文本 `'7.5%'` 时 Excel 参与算术会隐式转 `0.075`，Python 直接 `TypeError`。生成器**只在「缓存值本身就是数字样式文本」的列上**加数值化包装，不滥用 |
| 4 | **无匹配语义不同** | `SUMIFS/COUNTIFS/MAXIFS/MINIFS` 无匹配返回 `0`；`AVERAGEIFS` 返回 `#DIV/0!`；`XLOOKUP/VLOOKUP` 返回 `#N/A`。混同会让批量结果整片变 NaN |
| 5 | **`ROUND` 不是 numpy 的 round** | Excel 是「四舍五入远离零」（`ROUND(2.5,0)=3`），numpy 是银行家舍入（`=2`）。运行时用 `_round`/`_roundup`/`_rounddown` 复现 Excel 语义 |
| 6 | **Excel 侧错误要单独归类** | pandas 把 `#REF!`/`#N/A` 读成 `NaN`，会被误判成「空值」或「逻辑差异」。对账器额外用 openpyxl 读原始缓存值，归为 **Excel侧错误**，不计入一致率分母 |
| 7 | **常量命名映射的键格式** | 键由 `_skey(值)` 生成，**小数点写成下划线**：`1.13 → "1_13"`、`0.05 → "0_05"`、`-0.5 → "neg0_5"`。写成 `"1.13"` 永远查不到 |

### 3+1 层执行模型（分层只作统计）

```
数据层        从 Excel 读输入参数（手填列）
   ↓
Layer 1      直接引用        =B2
Layer 2      跨表操作        VLOOKUP / XLOOKUP / INDEX+MATCH / SUMIFS / COUNTIFS / …
Layer 3      其他公式        算术 / IF / ROUND / CEILING / RATE / FV / CUMIPMT / SUM(区域)
```

分层冲突（低层依赖高层）时**自动降级为全局拓扑排序**，结果等价。见「技术路径」中的取舍说明。

## 十、性能与验收口径

### 性能

生成代码是向量化的；`run_batch` 按 chunk（默认 200 条）调用 `calc`，工作簿句柄与 sheet 缓存跨 chunk 复用。

> **真实项目实测（已脱敏）**：100+ 列 / 13 张外部表 / 最大 8 层依赖 / 依赖表最大 8.8 万行 → **批量 50 条记录约 30 秒**。

### 验收口径

一次迁移只有**同时满足三条**才算完成：

| # | 指标 | 定义 |
|---|---|---|
| 1 | **转换覆盖率** | 公式列转换成功数 / 公式列总数 |
| 2 | **一致率（排除 Excel 侧错误）** | 生成代码 vs Excel 缓存值逐格对比 |
| 3 | **可批量** | 生成的代码能直接跑 N 条主键并产出结果表 |

**第 2 条不可替代**——它是对「生成代码是否算错」的唯一客观证据。
覆盖率 100% 只说明"都翻译了"，不代表"翻译对了"。
